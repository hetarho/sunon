## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로젝트 추가 버튼으로 새 프로젝트 생성 (Priority: P1)

사용자가 워크스페이스 홈 화면에서 "프로젝트 추가" 버튼을 클릭하면, 프로젝트명을 입력할 수 있는 다이얼로그가 표시된다. 프로젝트명을 입력하고 확인하면 워크스페이스 디렉토리 안에 해당 프로젝트명과 동일한 폴더가 생성되고, 미리 정해진 템플릿 구조(product.md 파일과 하위 폴더들)가 자동으로 생성된다. 생성 완료 후 프로젝트 목록에 새 프로젝트가 즉시 반영된다.

**Why this priority**: 핵심 기능이며, 이 기능 없이는 사용자가 앱 내에서 프로젝트를 생성할 수 없다. 현재는 외부에서 직접 폴더를 만들어야 하는 불편함이 있으므로 가장 높은 우선순위.

**Independent Test**: 워크스페이스가 열린 상태에서 프로젝트 추가 버튼을 누르고, 이름을 입력하고, 확인을 누른 뒤 파일 시스템에 올바른 폴더/파일 구조가 생성되었는지 확인

**Acceptance Scenarios**:

1. **Given** 워크스페이스가 열려 있고 프로젝트 목록이 비어 있는 상태, **When** 사용자가 "프로젝트 추가" 버튼을 클릭하고 프로젝트명 "my-project"를 입력 후 확인, **Then** 워크스페이스 경로 아래에 `my-project/` 폴더가 생성되고 프로젝트 목록에 "my-project"가 활성 상태로 표시된다
2. **Given** 워크스페이스에 이미 프로젝트들이 있는 상태, **When** 사용자가 새 프로젝트 "new-project"를 추가, **Then** 기존 프로젝트는 유지되고 "new-project"가 알파벳 순으로 정렬되어 목록에 추가된다
3. **Given** 프로젝트 생성 완료, **When** 파일 시스템을 확인, **Then** 프로젝트 폴더 하위에 다음 구조가 존재한다:
   - `product.md` (빈 파일)
   - `policies/data/`
   - `policies/format/`
   - `policies/system/`
   - `policies/ux/`
   - `policies/validate/`
   - `entities/`
   - `elements/`
   - `user stories/`
   - `specs/`

### User Story 2 - 프로젝트명 유효성 검증 (Priority: P2)

사용자가 프로젝트명을 입력할 때, 시스템이 입력값의 유효성을 검사한다. 빈 이름, 중복 이름, 파일 시스템에서 허용되지 않는 문자 등을 검증하여 사용자에게 즉각적인 피드백을 제공한다.

**Why this priority**: 잘못된 프로젝트명으로 인한 오류를 사전에 방지하여 사용자 경험을 보호한다.

**Independent Test**: 다이얼로그에서 다양한 유효/무효 프로젝트명을 입력하고, 적절한 오류 메시지가 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 프로젝트명 입력 다이얼로그가 열린 상태, **When** 빈 이름으로 확인 버튼을 누름, **Then** 오류 메시지가 표시되고 프로젝트가 생성되지 않는다
2. **Given** 워크스페이스에 "existing-project"가 이미 존재하는 상태, **When** 동일한 이름 "existing-project"를 입력, **Then** 중복 이름 오류 메시지가 표시되고 프로젝트가 생성되지 않는다
3. **Given** 프로젝트명 입력 다이얼로그가 열린 상태, **When** 파일 시스템에서 허용되지 않는 문자(예: `/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`)가 포함된 이름을 입력, **Then** 오류 메시지가 표시되고 프로젝트가 생성되지 않는다

---

### User Story 3 - 프로젝트 생성 중 오류 처리 (Priority: P3)

파일 시스템 권한 문제나 디스크 공간 부족 등의 이유로 프로젝트 생성이 실패할 경우, 사용자에게 명확한 오류 메시지를 표시하고 부분적으로 생성된 폴더를 정리(롤백)한다.

**Why this priority**: 비정상 상황에서도 일관된 상태를 유지하기 위한 안전장치이며, P1/P2보다 발생 빈도가 낮다.

**Independent Test**: 읽기 전용 디렉토리에서 프로젝트 생성을 시도하고, 오류 메시지가 표시되며 부분 생성된 폴더가 없는지 확인

**Acceptance Scenarios**:

1. **Given** 워크스페이스 디렉토리에 쓰기 권한이 없는 상태, **When** 프로젝트 생성을 시도, **Then** 사용자에게 권한 오류 메시지가 표시되고 불완전한 폴더가 남지 않는다
2. **Given** 프로젝트 폴더는 생성되었으나 하위 구조 생성 중 오류 발생, **When** 시스템이 오류를 감지, **Then** 부분적으로 생성된 프로젝트 폴더가 정리(삭제)되고 사용자에게 오류가 안내된다

---

### Edge Cases

- 프로젝트명에 한글, 공백이 포함된 경우: 허용한다 (파일 시스템에서 유효한 문자)
- 파일 시스템 금지 문자(`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`): 차단한다
- 프로젝트명 중복 검사는 대소문자를 무시한다 (macOS APFS/HFS+ 파일 시스템 호환)
- 프로젝트명이 매우 긴 경우: 255자 이하로 제한하고 초과 시 오류 메시지 표시
- 프로젝트명 앞뒤 공백: 자동으로 제거(trim)
- 프로젝트명이 마침표(`.`)로 시작하는 경우: 숨김 폴더가 되어 기존 스캔 로직에서 제외되므로 허용하지 않는다
- 다이얼로그에서 취소: 아무 작업도 수행하지 않고 다이얼로그를 닫는다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 워크스페이스 홈 화면에 "프로젝트 추가" 버튼이 표시되어야 한다
- **FR-002**: "프로젝트 추가" 버튼 클릭 시 프로젝트명을 입력받는 다이얼로그가 표시되어야 한다
- **FR-003**: 프로젝트명 확인 시 워크스페이스 경로 하위에 프로젝트명과 동일한 이름의 폴더가 생성되어야 한다
- **FR-004**: 생성된 프로젝트 폴더 하위에 `product.md` 빈 파일이 생성되어야 한다
- **FR-005**: 생성된 프로젝트 폴더 하위에 `policies/` 폴더가 생성되고, 그 안에 `data/`, `format/`, `system/`, `ux/`, `validate/` 하위 폴더가 생성되어야 한다
- **FR-006**: 생성된 프로젝트 폴더 하위에 `entities/`, `elements/`, `user stories/`, `specs/` 폴더가 생성되어야 한다
- **FR-007**: 프로젝트 생성 완료 후 프로젝트 목록이 자동으로 갱신되어 새 프로젝트가 표시되어야 한다
- **FR-008**: 빈 프로젝트명, 중복 프로젝트명(대소문자 무시 비교), 파일 시스템 금지 문자가 포함된 프로젝트명에 대해 유효성 검증 오류를 표시해야 한다
- **FR-009**: 마침표(`.`)로 시작하는 프로젝트명은 허용하지 않아야 한다
- **FR-010**: 프로젝트명의 앞뒤 공백은 자동으로 제거해야 한다
- **FR-011**: 프로젝트 생성 중 오류 발생 시 부분적으로 생성된 폴더를 정리(롤백)하고 사용자에게 오류 메시지를 표시해야 한다
- **FR-012**: 다이얼로그에서 취소 시 아무 작업도 수행하지 않아야 한다
- **FR-013**: 프로젝트 생성 완료 후 해당 프로젝트가 자동으로 활성(선택) 상태가 되어야 한다

### Key Entities

- **Project**: 워크스페이스 내의 독립적인 작업 단위. 이름(name)과 경로(path)를 가지며, 미리 정의된 템플릿 폴더 구조를 포함한다
- **Project Template Structure**: 프로젝트 생성 시 자동으로 만들어지는 표준 폴더/파일 구조 (product.md, policies, entities, elements, user stories, specs)
- **Workspace**: 프로젝트들을 포함하는 상위 디렉토리. 프로젝트 추가 시 이 디렉토리 하위에 폴더가 생성된다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 프로젝트명 입력부터 생성 완료까지 3초 이내에 완료할 수 있다
- **SC-002**: 생성된 프로젝트의 폴더 구조가 100% 정확하게 템플릿과 일치한다 (10개 하위 폴더 + 1개 파일)
- **SC-003**: 유효하지 않은 프로젝트명 입력 시 100% 사전 차단되어 파일 시스템에 불완전한 폴더가 생성되지 않는다
- **SC-004**: 프로젝트 생성 실패 시 롤백이 수행되어 부분 생성된 폴더가 0개 남는다
- **SC-005**: 프로젝트 생성 후 목록 갱신이 즉시(1초 이내) 반영된다

## Assumptions

- 워크스페이스가 이미 열려 있는 상태에서만 프로젝트 추가가 가능하다
- `product.md`는 빈 파일로 생성된다 (초기 내용 없음)
- `user stories` 폴더명에 공백이 포함되어 있으며, 이는 의도된 것이다
- 프로젝트명에 한글과 공백을 허용한다 (파일 시스템 유효 문자 범위 내)
- 프로젝트명 최대 길이는 운영체제별 파일 시스템 제한을 따른다 (macOS: 255자)
