## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로젝트 선택 시 사이드바 메뉴와 상세 페이지 표시 (Priority: P1)

사용자가 워크스페이스 홈 화면에서 프로젝트를 선택(활성화)하면, 화면이 프로젝트 상세 뷰로 전환된다. 좌측에 사이드바가 나타나고, sunon 문서 계층 순서대로 메뉴 항목이 표시된다:

1. Product
2. Entities
3. Policies
4. User Stories
5. Elements
6. Specs

기본으로 첫 번째 메뉴(Product)가 선택된 상태이며, 우측 콘텐츠 영역에 해당 메뉴의 페이지가 표시된다. 현재 모든 페이지는 TBD 플레이스홀더(페이지 이름만 표시)로 구현한다.

**Why this priority**: 프로젝트 내비게이션의 기본 골격으로, 이후 모든 세부 기능이 이 구조 위에 구현된다.

**Independent Test**: 프로젝트를 선택 → 사이드바에 6개 메뉴 확인 → 각 메뉴 클릭 시 우측에 해당 페이지 이름이 표시되는지 확인

**Acceptance Scenarios**:

1. **Given** 워크스페이스에 프로젝트가 존재하고 프로젝트 목록이 표시된 상태, **When** 사용자가 프로젝트를 선택(탭), **Then** 화면이 프로젝트 상세 뷰로 전환되며 좌측에 사이드바 메뉴 6개가 계층 순서대로 표시된다
2. **Given** 프로젝트 상세 뷰가 표시된 상태, **When** 초기 진입, **Then** 첫 번째 메뉴(Product)가 선택된 상태이고 우측에 "Product" TBD 플레이스홀더 페이지가 표시된다
3. **Given** 프로젝트 상세 뷰의 사이드바가 표시된 상태, **When** 사용자가 "Entities" 메뉴를 클릭, **Then** 해당 메뉴가 선택 상태로 변경되고 우측 콘텐츠 영역에 "Entities" TBD 플레이스홀더 페이지가 표시된다
4. **Given** 프로젝트 상세 뷰가 표시된 상태, **When** 사용자가 6개 메뉴를 순서대로 각각 클릭, **Then** 각 메뉴에 대응하는 TBD 플레이스홀더 페이지가 올바르게 전환된다

### User Story 2 - 프로젝트 상세 뷰에서 프로젝트 목록으로 복귀 (Priority: P2)

프로젝트 상세 뷰에서 사용자가 뒤로가기 또는 워크스페이스 이름을 클릭하면 프로젝트 목록 화면으로 돌아갈 수 있다.

**Why this priority**: 기본적인 내비게이션 완성. 상세 페이지에 진입한 후 다시 프로젝트 목록으로 돌아갈 수 없으면 사용성이 크게 저하된다.

**Independent Test**: 프로젝트 상세 뷰에서 뒤로가기 버튼 클릭 → 프로젝트 목록 화면으로 복귀 확인

**Acceptance Scenarios**:

1. **Given** 프로젝트 상세 뷰가 표시된 상태, **When** 사용자가 뒤로가기 버튼(또는 워크스페이스명)을 클릭, **Then** 프로젝트 목록 화면으로 돌아가고 이전 프로젝트 선택 상태는 유지된다
2. **Given** 프로젝트 목록으로 복귀한 상태, **When** 같은 프로젝트를 다시 선택, **Then** 프로젝트 상세 뷰로 다시 진입한다

---

### Edge Cases

- 프로젝트를 선택한 후 해당 프로젝트 폴더가 외부에서 삭제된 경우: 오류 메시지 표시 후 프로젝트 목록으로 복귀
- 사이드바 메뉴를 빠르게 연속 클릭한 경우: 마지막으로 클릭한 메뉴의 페이지가 표시된다
- 창 크기가 매우 작은 경우: 사이드바와 콘텐츠 영역이 최소 너비를 유지한다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 프로젝트를 선택하면 프로젝트 상세 뷰로 화면이 전환되어야 한다
- **FR-002**: 프로젝트 상세 뷰의 좌측에 사이드바가 표시되어야 한다
- **FR-003**: 사이드바에는 sunon 문서 계층 순서대로 6개 메뉴가 표시되어야 한다: Product, Entities, Policies, User Stories, Elements, Specs
- **FR-004**: 사이드바 메뉴 클릭 시 우측 콘텐츠 영역에 해당 메뉴의 페이지가 표시되어야 한다
- **FR-005**: 모든 메뉴 페이지는 TBD 플레이스홀더로, 페이지 이름만 표시한다
- **FR-006**: 프로젝트 상세 뷰 초기 진입 시 첫 번째 메뉴(Product)가 기본 선택되어야 한다
- **FR-007**: 현재 선택된 메뉴가 사이드바에서 시각적으로 구분되어야 한다
- **FR-008**: 프로젝트 상세 뷰에서 프로젝트 목록 화면으로 돌아갈 수 있는 뒤로가기 수단이 있어야 한다

### Key Entities

- **Sidebar Menu Item**: 사이드바에 표시되는 메뉴 항목. 이름(label)과 선택 상태(selected)를 가진다
- **TBD Placeholder Page**: 각 메뉴에 대응하는 임시 페이지. 페이지 이름만 텍스트로 표시한다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 프로젝트 선택 후 상세 뷰 전환이 1초 이내에 완료된다
- **SC-002**: 6개 메뉴 간 전환이 즉시(200ms 이내) 이루어진다
- **SC-003**: 사이드바 메뉴 항목 순서가 sunon 문서 계층과 100% 일치한다
- **SC-004**: 모든 6개 메뉴를 클릭했을 때 각각 올바른 페이지 이름이 표시된다

## Assumptions

- 사이드바 메뉴 순서는 sunon 문서 계층(constitution에 정의)을 따른다: Product → Entities → Policies → User Stories → Elements → Specs
- TBD 플레이스홀더 페이지는 중앙에 페이지 이름 텍스트만 표시하는 최소한의 UI이다
- 프로젝트 상세 뷰는 기존 워크스페이스 홈 화면을 대체하는 것이 아니라, 프로젝트 선택 시 전환되는 별도 뷰이다
- 뒤로가기는 AppBar의 뒤로 버튼으로 제공한다
