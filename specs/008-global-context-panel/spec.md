# Feature Specification: Global Context Panel (우측 컨텍스트 패널)

**Feature Branch**: `008-global-context-panel`
**Created**: 2026-04-05
**Status**: Draft
**Input**: User description: "엔티티 페이지에서 product 관련 정보를 보려면 product 페이지로 이동해야 해서 흐름이 끊김. 엔티티를 작성하면서도 '왜 이걸 하는지'를 알 수 있도록, 좌측 사이드바 말고 우측에 전역 패널을 만들어서 문서 계층상 참조 가능한 정보들을 우측 패널에서 접근 가능하게 한다."

## Design Rationale

sunon의 문서 계층(Document Architecture)은 클린 아키텍처의 의존성 규칙을 따른다:

| 계층 | 참조 가능 |
|------|-----------|
| product | 없음 |
| entities | product |
| policies | product, entities |
| userstories | product, entities, policies |
| elements | product, entities, policies |
| specs | 전부 |

현재 구현에서는 각 계층의 페이지가 독립적으로 존재하여, 엔티티를 편집하면서 product의 mission이나 principles를 확인하려면 페이지를 전환해야 한다. 이는 **"이 엔티티를 왜 정의하는가?"**라는 맥락을 잃게 만든다.

우측 컨텍스트 패널은 현재 작업 중인 계층에서 의존성 규칙에 따라 참조 가능한 상위 계층의 정보를 페이지 전환 없이 조회하고 **편집**할 수 있게 한다. 좌측 사이드바(NavigationRail)가 **어디로 갈지**를 결정한다면, 우측 패널은 **왜 여기서 이 작업을 하는지**에 대한 맥락을 제공하며, 필요하면 그 맥락을 즉시 수정할 수도 있다.

패널은 기존 페이지와 동일한 컴포넌트를 재사용하여 풀 편집을 지원한다. sunon이 지향하는 "변화에 유연한 구조"에 맞게, 엔티티를 편집하다가 product의 mission이 바뀌어야 한다면 페이지 전환 없이 패널에서 바로 수정할 수 있다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 패널 열기/닫기 토글 (Priority: P1)

사용자가 프로젝트 상세 뷰에서 우측 컨텍스트 패널을 열거나 닫을 수 있다. 패널은 메인 콘텐츠 영역의 오른쪽에 나타나며, 토글 버튼으로 제어한다. 패널 상태(열림/닫힘)는 세션 동안 유지된다.

**Why this priority**: 패널이 열리고 닫히는 기본 동작이 모든 후속 기능의 전제 조건이다.

**Independent Test**: 프로젝트 상세 뷰에서 토글 버튼 클릭 → 우측에 패널 영역이 나타남 → 다시 클릭 → 패널이 닫히는지 확인

**Acceptance Scenarios**:

1. **Given** 프로젝트 상세 뷰에 진입한 상태(패널 닫힘), **When** 우측 패널 토글 버튼을 클릭하면, **Then** 메인 콘텐츠 영역 오른쪽에 패널이 나타나고, 메인 콘텐츠 영역이 그만큼 줄어든다.
2. **Given** 패널이 열려 있는 상태, **When** 토글 버튼을 다시 클릭하면, **Then** 패널이 닫히고 메인 콘텐츠 영역이 전체 너비를 차지한다.
3. **Given** 패널이 열려 있는 상태에서, **When** 좌측 사이드바로 다른 메뉴(예: Product → Entities)로 이동하면, **Then** 패널은 열린 상태를 유지하며 현재 페이지에 맞는 컨텍스트로 내용이 갱신된다.

---

### User Story 2 - 엔티티 페이지에서 Product 정보 조회 및 편집 (Priority: P1)

사용자가 엔티티 페이지(리스트 또는 상세)에서 작업 중일 때, 우측 패널을 열면 Product 정보(Name, Mission, Principles)를 확인하고 **직접 편집**할 수 있다. 패널은 기존 Product 페이지와 동일한 편집 컴포넌트를 사용하여, 페이지 전환 없이 product 정보를 수정할 수 있다.

**Why this priority**: 이 기능의 핵심 동기 — 엔티티를 작성하면서 "왜 이걸 하는가?"에 대한 답(product의 mission/principles)을 즉시 확인하고, 필요하면 맥락을 바로 수정할 수 있어야 한다.

**Independent Test**: 엔티티 페이지에서 우측 패널 열기 → Product 섹션에서 mission 내용 수정 → product.md 파일에 자동 저장되는지 확인

**Acceptance Scenarios**:

1. **Given** 엔티티 리스트 페이지에서 우측 패널이 열린 상태, **When** 패널을 확인하면, **Then** Product 정보(Name, Mission, Principles)가 편집 가능한 폼으로 표시된다.
2. **Given** 엔티티 상세 페이지에서 칼럼을 편집 중인 상태, **When** 우측 패널에서 Product의 Mission을 수정하면, **Then** 디바운스 후 product.md 파일에 자동 저장된다.
3. **Given** 우측 패널에서 Product 정보를 수정한 후, **When** 좌측 사이드바에서 Product 메뉴로 이동하면, **Then** Product 페이지에 패널에서 수정한 내용이 반영되어 있다.
4. **Given** 엔티티 상세 페이지에서 칼럼 편집과 패널에서 Product Mission 편집을 동시에 진행 중인 상태, **When** 양쪽 모두 디바운스 저장이 발생하면, **Then** 각각의 파일(entity md, product.md)에 독립적으로 저장된다.

---

### User Story 3 - 현재 페이지에 따른 컨텍스트 자동 구성 (Priority: P2)

우측 패널의 내용은 현재 보고 있는 페이지의 계층에 따라 자동으로 결정된다. 의존성 규칙에 따라 참조 가능한 상위 계층의 정보만 표시한다.

- **Product 페이지**: 참조 가능한 상위가 없으므로 패널에 표시할 컨텍스트가 없음 (패널 버튼을 비활성화하거나, 빈 상태 안내)
- **Entities 페이지**: Product 정보 표시
- **Policies 페이지** (향후): Product + Entities 목록 표시
- **User Stories/Elements 페이지** (향후): Product + Entities + Policies 표시

**Why this priority**: 패널 내용이 현재 컨텍스트에 맞게 자동 구성되어야 사용자가 수동으로 원하는 정보를 찾지 않아도 된다.

**Independent Test**: Product 페이지 → Entities 페이지로 이동하면서 패널 내용이 변경되는지 확인

**Acceptance Scenarios**:

1. **Given** Product 페이지에 진입한 상태, **When** AppBar 우측의 패널 토글 버튼을 확인하면, **Then** 버튼이 비활성화(greyed out) 상태이며 클릭할 수 없다.
2. **Given** Entities 페이지에서 패널이 열린 상태, **When** 패널 내용을 확인하면, **Then** Product 섹션이 표시된다.
3. **Given** 패널이 열린 상태에서 좌측 사이드바로 다른 메뉴로 이동하면, **When** 이동한 페이지의 계층이 변경되면, **Then** 패널 내용이 해당 계층의 참조 가능한 정보로 갱신된다.

---

### User Story 4 - 패널 내 섹션 접기/펼치기 (Priority: P3)

패널에 여러 계층의 정보가 표시될 때(향후 policies 페이지 등에서), 각 계층 섹션을 접거나 펼칠 수 있다. 사용자가 현재 관심 있는 정보에 집중할 수 있도록 한다.

**Why this priority**: 초기 구현에서 entities 페이지는 product 정보만 표시하므로 접기/펼치기의 필요성이 낮다. 하위 계층 페이지가 구현되어 패널 내용이 많아질 때 가치가 높아진다.

**Independent Test**: 패널에 여러 섹션이 있을 때 섹션 헤더 클릭 → 해당 섹션이 접히거나 펼쳐지는지 확인

**Acceptance Scenarios**:

1. **Given** 패널에 여러 컨텍스트 섹션이 표시된 상태, **When** 특정 섹션의 헤더를 클릭하면, **Then** 해당 섹션의 내용이 접혀서 헤더만 남는다.
2. **Given** 접힌 섹션의 헤더를 클릭하면, **Then** 해당 섹션의 내용이 다시 펼쳐진다.

---

### Edge Cases

- `product.md` 파일이 존재하지 않는 경우: 패널의 Product 섹션에 "Product 정보가 아직 정의되지 않았습니다" 안내 메시지 표시
- `product.md` 파일이 비어있는 경우: 빈 Product 섹션 표시 (필드명만 표시, 내용 없음)
- 패널이 열린 상태에서 프로젝트 상세 뷰를 벗어나는 경우(뒤로가기로 프로젝트 목록으로 이동): 패널 상태 초기화
- 좁은 화면에서 패널을 열었을 때 메인 콘텐츠 영역이 지나치게 좁아지는 경우: 패널 최소/최대 너비 제한을 두어 콘텐츠가 읽기 어려울 정도로 줄어들지 않도록 함
- 참조 대상 파일이 외부에서 수정된 경우: 패널을 열거나 페이지를 전환할 때 파일을 다시 읽어 최신 내용을 반영
- 패널에서 Product Name을 변경한 경우: 기존 Product 페이지와 동일하게 폴더 rename이 수행되며, 메인 콘텐츠 영역의 엔티티 페이지 경로도 함께 업데이트된다
- 메인 콘텐츠와 패널에서 동시에 편집 중 저장 타이밍이 겹치는 경우: 서로 다른 파일을 편집하므로 충돌 없이 독립 저장

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 프로젝트 상세 뷰의 AppBar 우측에 컨텍스트 패널 토글 아이콘 버튼을 제공해야 한다 (뒤로가기 버튼의 대칭 위치).
- **FR-002**: 패널은 메인 콘텐츠 영역의 오른쪽에 나타나야 하며, 열릴 때 메인 콘텐츠 영역이 줄어들어야 한다 (오버레이가 아닌 레이아웃 분할).
- **FR-003**: 패널의 열림/닫힘 상태는 좌측 사이드바 메뉴 전환 시에도 유지되어야 한다.
- **FR-004**: 패널은 현재 페이지의 문서 계층에 따라 참조 가능한 상위 계층의 정보를 편집 가능한 형태로 표시해야 한다. 기존 페이지와 동일한 편집 컴포넌트를 재사용한다.
- **FR-005**: Entities 페이지에서 패널은 Product 정보(Name, Mission, Principles)를 편집 가능한 폼으로 표시해야 한다.
- **FR-011**: 패널에서의 편집은 기존 페이지에서의 편집과 동일한 자동 저장(디바운스) 동작을 따라야 한다.
- **FR-012**: 메인 콘텐츠 영역과 패널에서 동시에 다른 파일을 편집할 때, 각 파일의 저장은 독립적으로 동작해야 한다.
- **FR-006**: Product 페이지에서는 참조 가능한 상위 계층이 없으므로 패널 토글 버튼을 비활성화(greyed out, 클릭 불가)해야 한다.
- **FR-007**: 패널에 표시되는 정보는 해당 파일을 읽어서 최신 상태를 반영해야 한다.
- **FR-008**: 참조 대상 파일이 없거나 비어있는 경우, 적절한 안내 메시지를 표시해야 한다.
- **FR-009**: 패널에 여러 섹션이 있을 때 각 섹션을 접거나 펼칠 수 있어야 한다.
- **FR-010**: 패널은 너비 제한을 가져야 하며, 메인 콘텐츠 영역이 지나치게 줄어들지 않아야 한다.

### Key Entities

- **Context Panel**: 프로젝트 상세 뷰 우측에 표시되는 전역 패널. 열림/닫힘 상태를 가지며, 현재 페이지 계층에 따른 참조 정보를 포함한다.
- **Context Section**: 패널 내의 개별 계층 정보 블록. 접기/펼치기가 가능하며, 각 섹션은 하나의 문서 계층(product, entities 등)에 대응한다.
- **Layer Reference Rule**: 문서 계층 간 의존성 규칙. 현재 페이지 계층이 참조할 수 있는 상위 계층을 결정한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 엔티티 페이지에서 product 정보를 확인하기 위해 페이지를 전환하지 않고도 1초 이내에 패널을 열어 확인할 수 있다.
- **SC-002**: 패널 토글 후 콘텐츠가 표시되기까지 500ms 이내에 반응한다.
- **SC-003**: 좌측 사이드바 메뉴를 전환할 때 패널 상태가 유지되며, 내용이 자동으로 갱신된다.
- **SC-004**: 패널이 열린 상태에서도 메인 콘텐츠 영역의 핵심 기능(엔티티 편집, product 편집 등)을 정상적으로 사용할 수 있다.

## Assumptions

- 패널은 프로젝트 상세 뷰(ProjectDetailScreen) 레벨에서 전역적으로 관리한다. 개별 페이지(ProductPage, EntityListPage 등)는 패널의 존재를 알 필요 없다.
- 패널의 열림/닫힘 상태는 앱 재시작 시 초기화된다(닫힌 상태가 기본). 영구 저장은 하지 않는다.
- 패널에 표시되는 정보는 편집 가능하다. 기존 페이지와 동일한 컴포넌트를 재사용하여 풀 편집을 지원한다.
- 초기 구현에서는 Entities 페이지의 Product 참조만 구현한다. Policies, User Stories, Elements 페이지는 아직 구현되지 않았으므로 해당 계층의 패널 내용은 향후 확장한다.
- 패널 너비는 고정값으로 시작한다. 사용자가 드래그로 너비를 조절하는 기능은 초기 범위에 포함하지 않는다.
- Product 정보의 파싱은 기존 ProductService의 로직을 재활용한다.
